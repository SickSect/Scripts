# Звук — гайд

Как завести звук с нуля и как его настроить. Документ описывает контракт системы:
имена ассетов, полей и компонентов зафиксированы здесь, реализация им следует.

---

## 0. Разовая настройка проекта

Делается один раз, до первого звука.

**Папки**

```
Assets/
  Audio/
    Clips/            — сырые аудиофайлы (.wav / .ogg)
    Sounds/           — ассеты SoundDefinition
    Surfaces/         — ассеты SurfaceDefinition
  Resources/
    Core/
      AudioMixer      — (опционально) AudioMixer с группами
      SurfaceDatabase — ассет SurfaceDatabase
      TriggerSounds   — ассет TriggerSoundMap
      UIAudio         — префаб с компонентом UIAudio
```

Из `Resources/Core/` система грузит ассеты сама, без ссылок в инспекторе.
Чего нет — то просто не работает, ошибок не будет (пишется warning в консоль,
как с `ItemDatabase` и `PhaseGraph`).

**Микшер — опционально.** Без него громкости считаются множителями в коде,
всё работает. Если хочешь эффекты (реверб в подъезде, лоу-пасс в паузе) —
создай `AudioMixer` с группами ровно с такими именами:

```
Master
├── Music
├── Ambient
├── SFX
├── UI
└── Player
```

Имена групп должны совпадать с элементами `AudioCategory` — по ним идёт
маршрутизация. Экспонировать параметры громкости не нужно, сервис пишет
громкость в источники напрямую.

**Настройки импорта клипов** — важнее, чем кажется:

| Тип звука | Load Type | Compression | Force To Mono |
|---|---|---|---|
| Короткий SFX (шаг, щелчок, скрип) | Decompress On Load | ADPCM или PCM | ✓ если 3D |
| UI (клик, открытие меню) | Decompress On Load | PCM | ✓ |
| Фон/петля (комната, улица, дождь) | Streaming | Vorbis, quality ~70 | ✗ если стерео-фон |
| Музыка | Streaming | Vorbis | ✗ |

Правило: всё, что звучит **в точке мира** (3D), должно быть моно. Стерео-клип
в 3D-источнике теряет позиционирование.

## 1. Создать звук

Меню: **Create → Core → Audio → Sound**. Один ассет = один звук в игре
(не один файл — у одного звука может быть 5 вариантов клипа).

Именование: `SND_<категория>_<что>` — `SND_SFX_DoorCreak`, `SND_AMB_StudioRoom`,
`SND_UI_MenuOpen`, `SND_PLR_StepWood`.

### Поля SoundDefinition

**Базовое**

| Поле | Что делает |
|---|---|
| `id` | Строка для логов и дебага. Не влияет на логику. |
| `clips` | Список клипов. Играется случайный, подряд один и тот же не повторяется. Один клип — тоже нормально. |
| `category` | `Music / Ambient / SFX / UI / Player`. Определяет группу микшера и ползунок громкости в настройках. |

**Громкость и высота**

| Поле | Дефолт | Что делает |
|---|---|---|
| `volume` | 1 | Базовая громкость. Умножается на громкость категории и мастера. |
| `volumeJitter` | 0 | Разброс ±. `0.1` → каждый раз 0.9–1.1 от базовой. |
| `pitch` | 1 | Базовая высота. |
| `pitchJitter` | 0 | Разброс ±. **Главный инструмент против «пулемёта»** — для шагов ставь 0.08–0.12. |

**Пространство**

| Поле | Дефолт | Что делает |
|---|---|---|
| `spatial` | ✗ | ✗ = 2D, звучит везде одинаково (UI, музыка, глобальный фон). ✓ = 3D, привязан к точке. |
| `minDistance` | 1 | Ближе этого расстояния громкость не растёт. Радиус «источника». |
| `maxDistance` | 20 | Дальше этого не слышно. |
| `rolloff` | Logarithmic | Как падает громкость. Logarithmic — реалистично, Linear — предсказуемо для зон. |

**Поведение**

| Поле | Дефолт | Что делает |
|---|---|---|
| `loop` | ✗ | Петля. Обязательно для фонов, запрещено для one-shot. |
| `fadeIn` | 0 | Секунд на нарастание. Для петель — 1–3 сек, иначе слышен щелчок включения. |
| `fadeOut` | 0 | Секунд на затухание при остановке. |
| `cooldown` | 0 | Минимум секунд между повторными запусками этого звука. Защита от спама (зона на границе коллайдера, спам-интеракт). |
| `maxInstances` | 4 | Сколько экземпляров звучит одновременно. Пятый вытесняет самый старый. |
| `ignorePause` | ✗ | Играть при `Time.timeScale = 0`. Обязательно ✓ для всех `UI`-звуков, иначе меню будет немым. |

**Минимальный рабочий набор:** кинуть клип в `clips`, выбрать `category`, всё
остальное оставить дефолтным. Дальше — по вкусу.

## 2. Подключить звук

Пять способов. Выбирается по тому, **что** должно звук запустить.

### 2.1. Звук при входе в зону

Компонент **`SoundTriggerZone`** на пустом объекте с коллайдером
(`Is Trigger` = ✓ — обязательно, иначе не сработает и заодно сломает рейкаст
взаимодействия).

| Поле | Что делает |
|---|---|
| `eventId` | Стабильный id для сохранения факта срабатывания. Уникальный в пределах сцены. |
| `soundOnEnter` | Звук при входе. Можно пусто. |
| `soundOnExit` | Звук при выходе. Можно пусто. |
| `condition` | `TriggerCondition` — тот же ассет условия, что у сюжетных событий. Не выполнено → тишина. |
| `onceOnly` | Сработать один раз. |
| `persistOnce` | Помнить срабатывание между заходами на сцену (пишется в сейв как сценовая метка). |
| `playAt` | `ZoneCenter` — звук в центре зоны (3D). `Player` — на игроке (звучит «в голове»). |

Работает как `StoryEventZone`, только без действий. Если по входу в зону нужен
и звук, и что-то ещё — не плоди зоны, поставь `StoryEventZone` и повесь в её
список действий `PlaySoundAction` (см. 2.3).

### 2.2. Локальный фон в определённом месте

Компонент **`AmbientZone`** на объекте с триггер-коллайдером. Фон нарастает при
входе и гаснет при выходе, автоматически, без событий.

| Поле | Что делает |
|---|---|
| `ambient` | `SoundDefinition` с `loop` = ✓. |
| `priority` | Кто кого перебивает. Больше = важнее. |
| `volumeScale` | Множитель поверх громкости самого звука — подкрутить конкретную зону, не трогая ассет. |
| `fadeTime` | Секунды на вход/выход. 1.5–3 — норма, 0.2 — резкий переход (за дверью). |

**Как складываются фоны.** `AmbientController` держит стек: базовый фон сцены
внизу, зоны сверху по приоритету. Слышен всегда только верхний — остальные
приглушены до нуля, но не остановлены, поэтому возврат в предыдущую зону
происходит без рестарта петли.

Вложенные зоны работают: комната (priority 0) → внутри неё ванная (priority 10).
Вышел из ванной — вернулся фон комнаты, плавно.

Равные приоритеты — неопределённое поведение. Не делай так.

### 2.3. Звук от сюжетного события

Ассет действия: **Create → Core → Story → Actions → Play Sound**. Кладётся в
список `actions` любого `StoryEventZone` / `StoryEventInteractable` / фазового
спавна — туда же, где `GiveTriggerAction` и `ScareAction`.

| Поле | Что делает |
|---|---|
| `sound` | Что играть. |
| `at` | `EventOrigin` — в точке события. `Player` — на игроке. `Global2D` — везде (для «удара судьбы»). |
| `delay` | Задержка в секундах. Для звука, который должен догнать визуал. |

Рядом лежит **Set Ambient** (`SetAmbientAction`) — меняет **базовый** фон сцены.
Это инструмент для фаз: день → вечер → ночь, у каждой свой фон студии.
Поле `ambient` пустое = тишина. `fade` — время перехода.

### 2.4. Звук на выдачу триггера

Когда звук должен звучать при получении флага **откуда угодно** — из диалога,
из интеракта, из фазы — не надо вешать `PlaySoundAction` в десяти местах.

Ассет **`TriggerSoundMap`** в `Resources/Core/TriggerSounds`: таблица
`TriggerDefinition → SoundDefinition`. Флаг выставился — звук сыграл.

| Поле строки | Что делает |
|---|---|
| `trigger` | Ассет триггера. |
| `sound` | Что играть. |
| `at` | `Player` или `Global2D`. Точки события тут нет — источник неизвестен. |

Годится для «дзынь, узнал важное», «щелчок записи в дневник». Для звука,
привязанного к конкретному объекту, используй 2.3.

### 2.5. Звуки интерфейса

Префаб **`UIAudio`** в `Resources/Core/UIAudio`. Один на всю игру, поднимается
в `GameBootstrap`, слушает сигналы `PAUSE_GAME` / `CONTINUE_GAME` — то есть
реагирует на **любой** блокирующий экран: паузу, инвентарь, диалог.

| Поле | Что делает |
|---|---|
| `screenOpen` | Звук открытия экрана. |
| `screenClose` | Звук закрытия. |
| `buttonHover` | Наведение на кнопку меню. |
| `buttonClick` | Нажатие. |
| `duckCategories` | Какие категории приглушать, пока экран открыт. Обычно `Ambient` + `SFX` + `Player`. |
| `duckFactor` | До скольки приглушать. `0.25` = до четверти. `0` = полная тишина. |
| `duckFade` | Секунды на приглушение и возврат. 0.15–0.4. |

Все четыре звука обязаны иметь `category = UI` и `ignorePause` = ✓. Без второго
они не прозвучат — меню ставит `timeScale = 0`.

«Отключение при выходе из меню» — это и есть `duck`: фон не останавливается,
а приглушается и возвращается на место. Останавливать петлю при паузе нельзя,
она перезапустится с начала и это слышно.

## 3. Звуки игрока

Компонент **`PlayerAudio`** на префабе игрока, рядом с `PlayerMovement`.

### Шаги

Шаги считаются **процедурно**, по пройденному расстоянию — Animation Events не
используются, к анимации не привязано. Прошёл `stepDistance` метров → шаг.

| Поле | Дефолт | Что делает |
|---|---|---|
| `stepDistanceWalk` | 1.8 | Метров на шаг при ходьбе. Меньше = чаще. |
| `stepDistanceRun` | 2.4 | При беге. Больше, чем при ходьбе — шаг длиннее. |
| `runVolumeScale` | 1.3 | Бег громче. |
| `groundMask` | — | Слои, которые считаются полом. |
| `rayOrigin` | — | Точка, откуда бьёт луч вниз. Ставь на уровень таза, не в ноги. |
| `rayDistance` | 1.5 | Длина луча. |
| `defaultSurface` | — | Что играть, если поверхность не опознана. Обязательно заполни. |

Подгонка каденции: если шаги «отстают» от ног — уменьшай `stepDistance`; если
частят — увеличивай. Ориентир для человеческого шага — 1.6–2.0 м.

### Поверхности

**Создать поверхность:** Create → Core → Audio → Surface. Именование `SUR_Wood`,
`SUR_Concrete`, `SUR_Tile`, `SUR_Carpet`.

| Поле | Что делает |
|---|---|
| `id` | Для логов. |
| `footsteps` | `SoundDefinition` шага. Минимум 4–5 клипов внутри + `pitchJitter` 0.1, иначе слышна повторяемость. |
| `footstepsRun` | Отдельный набор для бега. Пусто → берётся `footsteps` с `runVolumeScale`. |
| `landing` | Приземление. Опционально. |

**Как определяется поверхность в момент шага**, по порядку:

1. `SurfaceTag` на коллайдере под ногами (или на его родителе) — компонент с одним
   полем `surface`. Явное указание, приоритет высший.
2. `SurfaceDatabase` из `Resources/Core/SurfaceDatabase` — таблица
   `PhysicsMaterial → SurfaceDefinition`. Работает автоматически для всей
   геометрии с физматериалом.
3. `defaultSurface` с `PlayerAudio`.

Рабочая схема: физматериалы на модульных стенах/полах из Blender + база →
покрывает 90% сцены бесплатно. `SurfaceTag` вешается точечно, где нужно
исключение (ковёр в комнате, металлическая решётка).

### Дыхание

Тянется от стата выносливости — того же, что привязан к `PlayerMovement`.

| Поле | Что делает |
|---|---|
| `breathCalm` | Спокойное дыхание, петля. Можно пусто. |
| `breathHeavy` | Тяжёлое, петля. |
| `breathThreshold` | Доля выносливости (0..1), ниже которой включается тяжёлое. `0.35` — норма. |
| `breathRecover` | Доля, выше которой возвращается спокойное. Должна быть **больше** порога, иначе на границе будет дребезг. `0.6`. |
| `breathFade` | Кроссфейд между состояниями, 1–2 сек. |

Оба клипа — `category = Player`, `loop` = ✓, `spatial` = ✗.

## 4. Громкости

Три множителя перемножаются: `громкость категории × мастер × volume звука`.

Настройки живут в `PlayerPrefs`, не в сохранении — они привязаны к машине,
а не к слоту. Ключи: `audio.master`, `audio.music`, `audio.ambient`,
`audio.sfx`, `audio.ui`, `audio.player`.

Ориентиры при сведении (в `volume` самого ассета):

| Что | Диапазон |
|---|---|
| Фон комнаты | 0.15 – 0.3 |
| Уличный фон | 0.25 – 0.4 |
| Шаги | 0.4 – 0.6 |
| Скрип двери, интеракт | 0.6 – 0.8 |
| UI | 0.5 – 0.7 |
| Скример / удар | 1.0 |

Сводить надо **на одной громкости системы, от тихого к громкому**: сначала фоны,
потом шаги поверх них, потом всё остальное. Не наоборот — иначе фон окажется
неслышным.

## 5. Если звук не играет

По порядку, сверху вниз:

1. `clips` пустой или клип не назначен.
2. `volume` = 0, или громкость категории в настройках = 0.
3. Экран паузы открыт, а у звука нет `ignorePause`.
4. Зона: коллайдер без `Is Trigger`, или на нём нет `Rigidbody` ни на одной
   стороне, или игрок не проходит проверку `PlayerMovement` в родителях.
5. Зона: `onceOnly` + `persistOnce` — уже сработало и записано в сейв. Проверь
   сценовые метки, начни новую игру.
6. `condition` не выполнено — смотри лог `[Audio]`.
7. 3D-звук: `maxDistance` меньше, чем реальное расстояние до игрока. Или
   клип стерео (в 3D позиционируется криво либо не слышен).
8. `cooldown` съел повтор.
9. `maxInstances` исчерпан — звук вытеснен более новым.
10. Фон: не `loop`, поэтому отыграл один раз и замолчал.
11. Фон: перекрыт зоной с более высоким `priority`.

Диагностика: `CoreLog` уже включён, все запуски звука пишутся как
`[Audio] <id> → <категория> @ <позиция>`. Если строки нет — звук вообще не
дошёл до сервиса, проблема выше по цепочке (условие, зона, событие). Если
строка есть, а звука нет — проблема в настройках самого ассета или громкостей.

## 6. Рецепты

**Скрипящая дверь.** `SND_SFX_DoorCreak`: 3 клипа, `spatial` ✓, `minDistance` 1,
`maxDistance` 12, `pitchJitter` 0.06. Вешается `PlaySoundAction` (`at = EventOrigin`)
на `StoryEventInteractable` двери.

**Гудение лампы в коридоре.** `SND_AMB_Fluorescent`: 1 длинный клип, `loop` ✓,
`spatial` ✓, `minDistance` 2, `maxDistance` 8, `volume` 0.2. Компонент
`AmbientZone` с коллайдером по размеру коридора, `priority` 5, `fadeTime` 1.5.

**Фон студии, меняющийся по фазам.** `SND_AMB_StudioDay` / `StudioNight`:
`loop` ✓, `spatial` ✗, `volume` 0.25, `fadeIn` 3. Базовый фон ставится
`SetAmbientAction` в спавне фазы — `priority` не нужен, это нижний слой.

**Шаги по паркету.** `SND_PLR_StepWood`: 6 клипов, моно, `spatial` ✓,
`minDistance` 0.5, `maxDistance` 10, `volume` 0.5, `pitchJitter` 0.1,
`maxInstances` 3, `cooldown` 0.15. Оборачивается в `SUR_Wood`, физматериал
паркета маппится на него в `SurfaceDatabase`.

**Открытие паузы.** `SND_UI_MenuOpen`: 1 клип, `category` UI, `spatial` ✗,
`ignorePause` ✓, `volume` 0.6. В `UIAudio` → `screenOpen`.

## 7. Чего в системе нет

Сознательно, чтобы не разрастаться:

- Музыкальных переходов по тактам и адаптивного слоения. Музыка — обычная петля
  через `Ambient`/`Music`.
- Реверб-зон. Делаются штатными `Audio Reverb Zone`, система им не мешает.
- Окклюзии (звук за стеной глухой). Если понадобится — отдельным слоем поверх,
  через лоу-пасс на группе микшера.
- Субтитров и привязки звука к репликам диалога — это зона `DialoguePlayer`,
  отдельная задача.
